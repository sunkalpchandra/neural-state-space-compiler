# Skill: paper-writing

## Purpose
The paper (`paper/`) is **out of scope by owner decision** (CLAUDE.md, decision D-005).
This skill therefore governs the only "writing" that ships: `README.md`, `docs/`,
`research/*.md`, figure captions, and compile reports. The same standards a reviewer
would apply to a paper apply to these.

## Relevant theory
- Claims have three parts: statement, evidence pointer, scope/limitations. A sentence
  missing any of these is not allowed in README/docs.
- Hedging is information, not weakness: "on 5 seeds, in-distribution, recursive mode,
  H ≤ 250" tells the reader where the claim stops.
- Negative and null results are reported with the same prominence as positive ones.

## Project-specific conventions
- README structure: What it does → Research question → How to run (3 commands) →
  Current evidence (table generated by `scripts/make_tables.py`, with EXP ids) →
  Hypotheses status (H1–H7: `supported | not supported | mixed | untested`, each with a
  link to `research/experiment_log.md`) → Limitations → Reproducibility → License.
- Every number in README/docs is copied from a generated table or figure caption and
  carries its EXP id in a footnote or adjacent parenthesis.
- Forbidden phrases unless a registered benchmark shows it with CIs: "outperforms
  existing methods", "state of the art", "recovers the true dynamics", "learns the
  physical variables". Allowed with evidence: "matches within X", "lower error at
  H ≥ 100 on k of m systems", "linear alignment R² = ...".
- Compile reports (`docs/compiler.md`) are written by code; the template lives in
  `nssc/compiler/report.py`, its wording follows the same rules.
- If someone later writes a paper, `docs/experiments.md` + `research/experiment_log.md`
  are the source; nothing here should have to be reinterpreted.

## Implementation requirements
- `scripts/make_tables.py --readme` regenerates the README evidence block between
  `<!-- BEGIN RESULTS -->` / `<!-- END RESULTS -->` markers; the block is never edited
  by hand.
- Docs referencing figures use the stable ids F1–F10 (`scientific-visualization.md`).
- Limitations section lists: synthetic-only evidence (until K runs), n = 5 seeds,
  compute used, systems where compiled model lost.

## Common failure modes
- README updated with a promising preliminary run (seeds 0–1) that later regresses.
- Copying a number from a terminal into README (untraceable).
- Latent-variable interpretation stated as fact.
- Silent removal of a hypothesis that was falsified.

## Validation checklist
- [ ] Every claim: statement + EXP id + scope.
- [ ] Hypotheses status table present and matches `research/experiment_log.md`.
- [ ] No forbidden phrases; limitations present.
- [ ] Results block regenerated by script.
